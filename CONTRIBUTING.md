# Contributing

Keep changes small and focused. Explain the problem, the proposed change and the validation performed.

- Create a branch from `main` and submit a pull request.
- Preserve public interfaces unless a change is explicitly documented.
- Use clear names and docstrings for mathematical assumptions, units and conventions.
- Include regression tests for changes to numerical methods. State tolerances and their justification.
- Keep research notebooks reproducible. Identify data sources, sample periods, random seeds and limitations.
- Run the existing tests and review the resulting figures. See the repository README and `docs/publishing.md` for project-specific instructions.
- Do not commit credentials, private data or generated caches.
